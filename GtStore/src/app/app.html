Angular signals, in action

A signal is a getter around a current value. Angular tracks where it is read and updates interested consumers when that value changes.

This page uses APIs available in this project's Angular 21 installation. The root component uses OnPush change detection.

Dependency tracking

Reactive contexts

Templates, computed(), and effect() are reactive contexts. Signal reads made synchronously in them become dependencies.

Computed values and dynamic dependencies

cartSummary reads showSubtotal every time, but reads subtotal only while the subtotal is shown. Computeds are read-only, lazy, and memoized.

{{ cartSummary() }}

computed(() =>
  showSubtotal() ? subtotal() : 'hidden'
)

Read without tracking with untracked()

This computed tracks the name, not the incidental counter. Changing the counter alone leaves the summary cached; changing the name recomputes it.

Incidental counter: {{ incidentalCount() }}

{{ untrackedSummary() }}

computed(() =>
  trackedName() + ' / ' + untracked(incidentalCount)
)

Async work loses the reactive context

The effect tracks asyncRun. It reads theme only after a promise boundary, so changing the theme does not rerun that effect.

Current theme: {{ theme() }}

{{ asyncResult() }}

effect(() => {{ '{' }}
  const run = asyncRun(); // tracked
  Promise.resolve().then(() => theme()); // not tracked
{{ '}' }})

Assert an API is outside a reactive context

Use assertNotInReactiveContext() inside imperative APIs that must not be called from a computed or effect. This button handler is outside one.

{{ assertionMessage() }}

assertNotInReactiveContext(myApi);

Effects for non-reactive APIs

This component's constructor creates an effect() that logs quantity changes with console.info(). Use effects to synchronize with imperative APIs, not to copy state between signals.
